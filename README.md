# Homelab

自宅で設計・構築・運用している仮想化基盤「Homelab」の公開用まとめです。自分専用の実験環境ではなく、友人など他の利用者も日常的に使う基盤として運用しています。そのため、可用性、バックアップ、監視、電源障害への備えまで含めて、実際の運用環境として維持しています。

> このリポジトリは公開用に再構成した記録です。内部アドレス、機器を識別する情報、管理用ドメイン、実際の設定値などは記載していません。

## 概要

- Proxmox VEの2ノードクラスタを中核にした自宅仮想化基盤
- Raspberry PiをQDeviceとして追加し、2ノードでもクラスタの過半数を維持できる構成
- ZFS RAIDZ2による共有ストレージ兼バックアップ基盤
- サーバー間とメインPC間を10GbE化し、実測で約9.5Gbpsの転送を確認
- 主要ゲストに1分間隔のZFSレプリケーションとHAを設定し、ノード停止時の自動復旧を試験済み
- UPSによる停電時の正常停止と、復電後の自動復旧を実機で試験済み
- 監視と障害通知、バックアップからの復元試験までを運用に含めている

## 現在の構成

| 領域 | 構成・方針 |
|---|---|
| 仮想化 | Proxmox VEの2ノードクラスタ |
| 過半数維持 | Raspberry PiをQDeviceとして使用 |
| ストレージ | 8TB HDDを4台使ったZFS RAIDZ2プールを、NASとバックアップ基盤として併用 |
| ネットワーク | サーバー間・メインPC間を10GbE化 |
| 可用性 | 主要ゲストを1分間隔で別ノードへレプリケーションし、HAを有効化 |
| 電源 | UPSを導入し、停電時の自動正常停止と復電後の自動復旧を設定 |
| 管理アクセス | LAN内とVPN経由に限定 |
| 外部公開 | Minecraftサーバー用に必要な通信1つだけを公開し、管理画面やリモート管理は公開しない |

片方のノードには大容量メモリを搭載し、メモリテストの全パス合格を確認しています。CPU世代の異なるノード間のライブマイグレーションは、検証環境で不具合を再現したため採用せず、保守時は停止移行に統一しています。

## 稼働しているサービス

- 友人向けMinecraftサーバー
- 友人が利用するWebアプリケーションと、GitHub Actionsのセルフホストランナー
- ネットワーク機器などのログを集約するコンテナ
- 死活監視とリソース監視を行うコンテナ
- GPUをPCIeパススルーした計算用VM。音声認識の推論環境として利用
- Discord Bot用VM

## 利用者と運用

この基盤は本人以外も利用しているため、運用では「動いていること」だけでなく「利用者が快適に使えること」を意識しています。

- 利用するサービスや利用者の使い方に合わせて、VMやコンテナへのCPU・メモリなどのリソース配分を調整している
- 遅延などが生じた場合は、監視や性能計測の結果を見ながら、設定やソフトウェア面のメンテナンスで改善を図っている
- Minecraftサーバーのように負荷が読みやすいものは実測値をもとに設定を決め、体感に影響する問題は利用者からの報告も手がかりに対応している

## 運用で重視していること

### バックアップではなく「戻せること」を確認する

VMバックアップを毎日自動取得し、別の保存先にも世代を保持しています。さらに、バックアップから隔離環境へ復元し、ハッシュ値の照合と起動確認まで行う復元試験を実施しています。

### 障害を前提に自動復旧と電源対策を行う

主要ゲストにはZFSレプリケーションとHAを設定し、ノード停止試験で別ノードへの自動復旧を確認しました。UPSについても、停電時にクラスタ全体を正常停止し、復電後に自動で戻る手順を実機で確認しています。

### 監視結果を通知までつなげる

Uptime Kuma、Prometheus、Grafana、Blackbox Exporter、Node Exporterなどを使い、死活とリソースを監視しています。障害と復旧はDiscordへ自動通知し、状態を見に行かなくても変化に気付けるようにしています。

### 構成と変更履歴を台帳で管理する

物理機器、VM、コンテナ、ネットワーク、バックアップ、変更履歴を台帳で一元管理しています。台帳にはパスワードなどの秘密値を記録せず、公開用資料では内部情報を除く運用にしています。

## Minecraftサーバー運用

友人向けに最大8人で利用するMinecraft Java Editionサーバーを、Homelab上のVMで運用しています。

- FabricベースのMOD環境をDocker Composeで管理
- 最適化、性能計測、操作履歴、Discord連携などのサーバーMODを導入
- クライアント側MODパックを配布し、参加者が同じ環境を再現できるようにしている
- 性能計測ツールでTPSとMSPTを実測しながら負荷設定を決め、全測定区間でTPS 20.0を維持
- 整合性を取りながら定期バックアップを行い、別の保存先にも独立コピーを保持
- バックアップからの隔離復元、ハッシュ値照合、同一イメージでの起動確認を実施済み
- MODは安定版を優先し、性能系MODも実測で必要性を確認してから追加する
